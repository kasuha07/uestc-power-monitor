# ADR-0001: 无人值守 reauth 的恢复策略（--reauth + 等待模式）

2026-08-07 决定：power-monitor 运行期触发 reauth（多因子二次认证）且无人值守时，
**不自动重试登录**（避免拿账号撞锁），而是：发送 `ReauthPending` 通知（首次立即、
之后每 30 分钟冷却重复）→ 进入等待模式 → 按轮询间隔从磁盘重载 cookie 文件并探测
会话 → 人工在终端运行 `uestc-power-monitor --reauth`（登录 + 交互完成 reauth + 保存
cookie 后退出，幂等）→ daemon 自动恢复并发送确认通知。

reauth 的三种可用方式（微信扫码/短信/企微码）都要求人工第二因素，且 TGT 是会话级
cookie、重登迟早再撞 reauth——无人值守与人工认证存在根本矛盾。曾考虑"告警后退出等
人工重启"（简单但打断监控）、"运行期远程交互"（复杂度高）；本方案让 daemon 持续
运行、人工只需一条命令即可恢复，且等待期不产生任何认证请求。
