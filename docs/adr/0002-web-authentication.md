# ADR-0002: Web 登录与监控共享认证状态

2026-09-30 决定：默认开启内嵌 Web 登录页，将进程启动与认证成功解耦。
容器初始化数据库和页面后即可保持运行，缺少凭证、登录失败、会话失效时等待人工登录。

Web 与监控共享一个 ApiService/UestcClient，所有认证、会话验证和采集通过同一异步锁
串行访问，避免多个 cookie store 相互覆盖。页面状态单独保存，扫码期间也可查询；
后台认证任务可取消，取消完成前不允许另一次认证。

密码只在本次认证请求中保留；ReauthContext 保存在进程内，由页面提交验证方式和
验证码。微信登录与二次认证通过认证库的二维码回调展示，保持原有协议、超时和轮询。
二维码由应用本地生成 SVG，不调用第三方二维码服务。

认证成功后验证电费门户会话并显式持久化 Cookie，再通过 Notify 唤醒监控。Web 模式
运行期会话过期时不重复自动登录，等待页面重新认证；临时网络或上游故障保留采集重试。

显式 Cookie 密钥优先，其次复用 `<cookie_file>.key`，再兼容现有密码派生方式；无凭证
时生成独立随机密钥。自动密钥和 Web 访问密钥采用 0600 文件，完整写入后原子发布。
页面接口使用随机访问密钥、Origin 校验、请求体限制和禁止缓存，不输出上游敏感错误。
Compose 默认只映射到宿主机回环地址，远程访问采用 SSH 转发或 HTTPS 反代。

`web.enabled = false` 保留 ADR-0001 的终端认证和独立登录恢复流程。Web 模式以页面
为恢复入口，外部 CLI 不作为运行中的 Web 模式的恢复信号，避免并发写入会话。

验证采用本机 HTTPS 代理模拟 CAS/微信/电费门户，执行真实客户端的加密、重定向、
Cookie 持久化与认证流程，不使用真实账号或向学校发送登录/验证码请求。
